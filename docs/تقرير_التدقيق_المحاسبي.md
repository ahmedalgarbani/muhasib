## 3. مشاكل عالية الخطورة 🟠 (تسبب أخطاء تراكمية)

### H1 - الرصيد مخزن لا محسوب (drift)

كل `journal` يحدث `UPDATE accounts SET balance = balance + ?` (`sales_invoice_accounting_service.dart:644`, `journal_local_datasource.dart:206`, `purchase...:424`).

لا يوجد `TRIGGER` ولا وظيفة تسوية. `lib/features/reports/data/datasources/reports_local_datasource.dart:462` يحسب الرصيد من `SUM(debit-credit)` للتقارير، بينما `customers.current_balance` و `accounts.balance` قد يختلفان. لا آلية `RECALCULATE`.

### H2 - صافي قيمة المخزون بعد الخصم (IAS2) منطق مرتبك

`lib/core/services/purchase_invoice_accounting_service.dart:309-358` يحسب `netInventory = inventoryValue - discount` ثم يضيف `otherFees` كـ `debit Inventory` منفصل – **لا يوزع `otherFees` وزنياً على `avg_cost`**. `avg_cost` يحسب في `_updateInventoryWithAverageCost` بـ `totalCost = lineTotalCost` فقط، فلا تتضمن الشحن → `COGS` أقل من الواقع.

### H3 - متوسط التكلفة لا يُعاد حسابه عند الإرجاع/الإلغاء

`lib/features/sales/data/datasources/invoice_local_datasource.dart:734-791`, `2843-2906` تسترجع `quantity` فقط: `UPDATE warehouse_stocks SET quantity = quantity +/- qty` دون إعادة `avg_cost`.

### H4 - تقارير الميزانية لا تقلب إشارة الخصوم/حقوق الملكية

`lib/features/reports/data/datasources/reports_local_datasource.dart:537` → `SELECT COALESCE(SUM(debit-credit),0) as net ... WHERE type IN (0,1,2)` ثم في `balance_sheet_report_page.dart:46` يعرض `displayAmount` كما هي. للخصوم الطبيعة دائنة (`credit - debit` موجب)، لكن الاستعلام يعطي سالباً.

### H5 - ازدواج جدول الفواتير

`invoices_table` (20 عمود) vs `sales_invoices_table` (مبسطة). مساران مختلفان لـ `payments`. التقارير تستخدم `invoices` فقط (`reports_local_datasource:169-173`) فتفوّت فواتير `sales_invoices`.

### H6 - حساب الخصم لا يفرق ضريبياً

لا يوجد فصل `VAT` على الخصم (قبل الضريبة أم بعد). `sales_invoice_accounting_service:74-75` يحسب `tax = (subtotal-discount)*rate` لكن `tax_ratio` قد يكون نسبة مئوية/عشرية.

### H7 - أرقام القيود غير ذرية (race)

`lib/core/services/sales_invoice_accounting_service.dart:997-1002` تولد `MAX(CAST(...))+1` داخل `transaction` (جيد) لكن `AccountingService:352-365` تولدها بدون `txn` في بعض المسارات.

## 5. تقييم كل وحدة محاسبية

### أ) الهيكل المحاسبي (دليل الحسابات / دفتر اليومية / دفتر الأستاذ)

**الجداول الأساسية:**
- `accounts`: `id, c_id UNIQUE, code UNIQUE, is_master, master_id FK, type, balance REAL, local_balance REAL` - جيد، لكن `type` بلا `CHECK`
- `journal_entries`: `number TEXT, total_debit/credit REAL CHECK>=0, difference CHECK<0.02, is_posted BOOL` + `reference_type/id` ممتاز للتدقيق
- `journal_entry_lines`: يمنع `debit+credit>0` و `NOT (both>0)` - ممتاز
- `daily_constraints / daily_constraint_lines`: نظام قيود يومية موازٍ لـ `journal` (تكرار يجب توحيده)

**الإيجابي:** تحقق `validateJournalEntryBalance` شامل + `hasChildAccounts/hasNonZeroBalance` قبل حذف حساب.
**السلبي:** `balance` لا يُحسب من `journal` - خطر drift؛ `type` متناقض؛ `c_id` مقابل `id` يربك `account_connects`.

### ب) الفواتير والمبيعات/المشتريات/المرتجعات

**المبيعات (`invoices.invoice_type=1,4`):**
- يحسب `subtotal - discount + tax + otherFee = finalAmt` مع تطبيع `taxRate >1 ? /100` - جيد
- يقسم `COGS` تناسبياً على كل دفعة + يقسم `discount/tax/other` - **يضمن توازن كل دفعة**
- ينشئ `journal` لكل دفعة + قيد مستحق للباقي - يدعم دفع مجزأ `cash+bank+credit`
- **المشكلة:** مساران - `SalesInvoiceAccountingService` يمر عبر `warehouse_stocks` بينما `AccountingService` يحدث `products.quantity` - جداول مخزون مختلفة

**المشتريات (`invoice_type=2,5`):**
- يطبق `netInventory = inventoryValue - discount` (يخفض المخزون بالخصم - يتماشى مع IAS2)
- **المشكلة:** `_round` فقط هنا؛ المبيعات لا تستخدمه → فروق `0.01`
- **المشكلة 2:** `otherFees` تضاف إجمالي لا موزع → `avg_cost` لا يعكس الشحن

**المرتجعات:** يعكس `COGS` بـ `avgCost` الحالي ويعيد `quantity` وينشئ قيود عكسية مع `REV`.
- **الجيد:** يمنع حذف فاتورة لها مرتجعات مرتبطة (`deleteInvoice:2665`)
- **السيء:** عند حذف مرتجع يفعل `quantity - returnQty` دون إعادة `avg_cost`

### ج) المخزون وتكلفة البضاعة (COGS)

- **الأسعار:** `categories.cost_amount, sell_amount`, `warehouse_stocks.avg_cost/last_cost/quantity`, `stock_movements.unit_cost/total_cost/balance_after`
- **طريقة التسعير:** `WAC` فقط (`newAvg = (oldQty*oldAvg + qty*unitCost)/newQty`) - مقبول لكن يجب توثيقه
- **المشاكل:** واجهتان `warehouse_stocks` vs `categories.quantity` - `getInventoryValuation` يحاول `COALESCE(SUM(ws.quantity), c.quantity)` كـ fallback؛ لا يوجد `reserved_quantity` مستخدم؛ لا يوجد جرد دوري حقيقي

### د) التقارير المالية

- **`trial_balance_datasource`:** يحسب `opening/period/closing` بـ `SUM(CASE WHEN entry_date < / BETWEEN)` مع `INNER JOIN je is_posted=1` - صحيح للتوازن لكن `HAVING` يخفي حسابات صفرية
- **`income_statement_datasource`:** يقسم الإيرادات `type=4/code 4%` والمصروفات `type=3/code 3%` - يفترض `type` المزروع؛ لو تم إصلاح `AccountType` سينقلب
- **`reports_local_datasource.getBalanceSheet*`:** يخلط أصول مدينة وخصوم دائنة بنفس الإشارة. الصحيح: `assets = debit-credit`, `liabilities/equity = credit-debit`
- **`general_ledger / account_statement`:** يحسب `runningBalance += debit-credit` - صحيح للأصول، خاطئ للخصوم إن عُرضت بذات المنطق

### هـ) المدفوعات والخزينة والبنوك

- **`unified_payments` + `payment_allocations`:** يدعم `receipt/payment voucher` مع `from/to Account`, `check, card, transfer` وحقول `commission_amount`
  - **الجيد:** `createPaymentJournalEntry` ينشئ `Dr To (net) + Dr Commission, Cr From (gross)` متوازن
  - **الجيد 2:** `markCheckBounced` ينشئ قيد عكسي + قيد رسوم منفصل
  - **المشكلة:** `cancelPayment` يعكس `allocated_amount` فقط

### و) العملات والضرائب والخصومات

- **العملات:** `currencies`, `currency_exchange_rates`, `currency_exchanges` - بنية ممتازة
  - **الجيد:** `CurrencyExchangeService` يحسب `diff = debitLocal - creditLocal` وينشئ فروق ربح/خسارة
  - **المشكلة:** عتبة `0.01` للربح/الخسارة و `0.005` لتحديث الرصيد - غير موحدة
- **الضرائب:** `taxes (name, ratio, account_id, tax_type)` - فصل ضريبة مدخلات (`1170`) vs مخرجات (`2170`) صحيح
- **الخصومات:** `discount_codes` + `discount_code_usage` - احترافي

### ز) سلامة البيانات والترحيل والتوازن

- **التوازن:** كل إنشاء قيد يتحقق `abs(totalDebit-totalCredit)>0.01` ويُنشئ `difference=0` - تغطية ممتازة
- **الترحيل:** `is_posted=1` مباشرة + منع تعديل/حذف المرحل إلا بـ `forceUpdate/forceDelete` - ممتاز
- **الإقفال:** `fiscal_periods (year, period, start/end, is_closed)` + فحص `SELECT is_closed WHERE start<=date<=end` في كل `process*` - لكن `period` سطر واحد سنوي فقط
- **الحذف:** لا يوجد `HARD DELETE` للقيود - `deleteInvoice` ينشئ `REV` مرآة ويعكس الأرصدة - يُحافظ على `audit trail`
